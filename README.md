# moy-chat 💬

**moy-chat** — это готовый к развертыванию безопасный закрытый чат для группы участников с поддержкой сообщений в реальном времени, отправкой файлов и push-уведомлениями. Проект спроектирован как легкий, надежный и расширяемый фундамент (baseline) для создания собственных корпоративных или приватных систем обмена сообщениями.

Демо-версия интерфейса: [all823218.web.app](https://web.app)

---

## ✨ Основные возможности

*   🔐 **Двойная авторизация:** Безопасный вход через Google (Firebase Auth) или Яндекс ID.
*   🛡️ **Бэкенд-верификация:** Вход через Яндекс проверяется на изолированном сервере с генерацией кастомных токенов Firebase.
*   👥 **Доступ по белому списку:** Писать и читать сообщения могут только пользователи, чьи email-адреса добавлены в список разрешенных.
*   ⚡ **Реальное время:** Моментальный обмен сообщениями на базе Firebase Realtime Database.
*   📁 **Обмен файлами:** Загрузка файлов размером до 20 МБ в S3-совместимое хранилище с последующим скачиванием по временным подписанным URL.
*   🔔 **Браузерные уведомления:** Оповещения о новых сообщениях через Web Push (сервис push браузера, рассылает `backend/index.py`) работают даже при закрытой вкладке.
*   🎨 **Кастомизация:** Встроенная светлая и тёмная темы, а также переключатель формата времени (12/24 часа).
*   👑 **Управление:** Возможность закрепления важных сообщений владельцем чата и удаление пользователями собственных сообщений.

---

## 🛠️ Архитектура проекта

Проект разделен на три изолированные части для обеспечения максимальной безопасности:

1.  **Frontend (`/`)**: Статический сайт (`index.html`, `app.js`). Отвечает за рендеринг интерфейса и логику на стороне клиента.
2.  **Backend (`/backend`)**: Серверная функция на **Python 3.12** для Яндекс Облака (работает за API Gateway). Отвечает за безопасный обмен токенов Яндекс, генерацию подписанных ссылок S3 и отправку push-уведомлений.
3.  **Admin Panel (`/admin`)**: Интерфейс управления списком участников чата, ведения системных журналов и администрирования.

## 🚀 Инструкция по установке и развертыванию

### Шаг 1. Настройка Firebase
1. Создайте проект в [консоли Firebase](https://google.com).
2. В разделе **Authentication** включите способ входа **Google**.
3. Создайте базу данных **Realtime Database** (выберите регион, наиболее близкий к вашим пользователям).
4. Загрузите правила безопасности базы данных из папки `admin/` вашего репозитория в соответствующую вкладку консоли базы данных.
5. Перейдите в настройки проекта -> вкладка «General» -> добавьте **Web-приложение**. Скопируйте объект с конфигурацией (ключи API, домены и т.д.).
6. Перейдите во вкладку «Service accounts» (Сервисные аккаунты), нажмите **Generate new private key** (Создать приватный ключ). Скачайте JSON-файл — он понадобится для бэкенда.

### Шаг 2. Настройка Яндекс ID (OAuth)
1. Зарегистрируйте новое приложение на портале [Яндекс Создание приложений](https://yandex.ru).
2. В доступах выберите: **«Яндекс ID (Паспорт)»** -> **«Доступ к адресу электронной почты»**.
3. В поле **Redirect URI** временно укажите адрес вашего будущего сайта (например, `https://localhost` для тестов или домен вашего хостинга).
4. Сохраните приложение и запишите полученный **Client ID**.

### Шаг 3. Развертывание бэкенда в Яндекс Облаке
1. В консоли [Yandex Cloud](https://yandex.ru) создайте бакет в **Object Storage** для хранения файлов чата. Создайте ключи доступа (Key ID и Secret Key) для этого бакета.
2. Создайте **Cloud Function** (версия Python 3.12) и загрузите в неё код из папки `/backend/index.py`.
3. Задайте для функции следующие **переменные окружения**:
   * `FIREBASE_SA_JSON`: Содержимое скачанного JSON-файла сервисного аккаунта Firebase.
   * `FIREBASE_DB_URL`: Ссылка на вашу Firebase Realtime Database.
   * `OWNER_EMAIL`: Ваш email (для автоматического назначения прав владельца чата).
   * `S3_BUCKET`: Имя вашего бакета Object Storage.
   * `S3_KEY_ID`: Идентификатор ключа S3.
   * `S3_SECRET`: Секретный ключ S3.
   * `VAPID_PRIVATE_KEY`: приватный ключ VAPID в формате PEM (пара к `VAPID` в `config.js`).
   * `VAPID_SUBJECT`: адрес вида `mailto:почта` для push-сервисов.
4. Создайте **API Gateway** в Яндекс Облаке и свяжите его с вашей функцией, чтобы получить публичный URL-адрес для запросов бэкенда.

### Шаг 4. Настройка конфигурации фронтенда
1. В корне проекта откройте файл `firebase-config.js` и вставьте туда данные вашего Web-приложения Firebase, полученные на *Шаге 1*.
2. Откройте файл `config.js` и заполните параметры:
   * Идентификатор приложения Яндекс (`Client ID`).
   * Публичный URL-адрес вашего развернутого бэкенда (`API Gateway`).
   * Публичный ключ `VAPID` для Push-уведомлений. Это пара к переменной `VAPID_PRIVATE_KEY` функции.

### Шаг 5. Публикация сайта
Вы можете бесплатно разместить статические файлы проекта (`index.html`, `app.js`, `config.js`, `firebase-config.js`, `sw.js`) на любом удобном хостинге:
*   GitHub Pages
*   Firebase Hosting
*   Яндекс Облако (статический сайт в Object Storage)

*Важно:* Не забудьте добавить домен вашего сайта в список **авторизованных доменов** в панели Firebase Authentication.

## 🔒 Безопасность и ограничения

*   **Защита данных:** Конфиденциальные ключи, токены и приватные списки почт исключены из коммитов с помощью `.gitignore` и хранятся исключительно в безопасном облачном окружении бэкенда.
*   **XSS-защита:** Все входящие текстовые сообщения проходят обязательное экранирование символов перед выводом на экран, что полностью исключает выполнение вредоносных скриптов.
*   **Ограничение токенов:** Проверка авторизации на стороне функции выполняется по умолчанию без мгновенного отзыва сессий (`check_revoked=False`), что оптимизирует скорость работы. Сессия Яндекс ID остается валидной в течение одного часа.
